# Семейный список покупок в Telegram Mini App — рекомендации по UI

> Основа: анализ KitchenOwl, Mealie, Tandoor Recipes, Grocy (ноябрь 2026).
> Назначение: спецификация UI/UX для реализации в Claude Code.

## 1. Скоуп

- **Что строим:** общие списки покупок. Пользователь создаёт списки и делится ими ссылкой; все подключившиеся редактируют список с одинаковыми правами. Без рецептов, плана меню, кладовой, расходов.
- **Клиент:** Telegram Mini App (Web App), открывается из бота: кнопка меню и inline-кнопка.
- **Бэкенд:** FastAPI.
- **Языки:** русский и испанский; английский желателен. Язык берётся из `language_code` пользователя Telegram, его можно переключить в настройках.
- **Главный критерий успеха:** участники пользуются списком вместо заметок или Bring!. Добавить товар — не больше 2 тапов плюс ввод текста. Изменение у второго участника видно меньше чем через 1–2 секунды.

## 2. Что взять из каждого приложения

| Источник | Что заимствуем | Почему |
|---|---|---|
| **KitchenOwl** (главный ориентир) | Строка поиска и добавления сверху; Enter добавляет первый результат; запятая отделяет описание («молоко, 2 л»); товары-плитки с иконками; блок «Недавние» для повторного добавления в один тап; realtime-синхронизация; выученный порядок товаров; режим «экран не гаснет»; Undo после удаления или отметки | Лучший UX списка покупок среди self-hosted решений, ощущается «как Bring!», нетехнические пользователи принимают его легко |
| **Tandoor** | Сущность «магазин» с собственным порядком отделов; некатегоризированный товар перетаскивается в отдел, и выбор запоминается | Единственная корректная модель для нескольких магазинов с разной планировкой (Mercadona ≠ Lidl) |
| **Mealie** | Видно, кто и откуда добавил позицию; поиск по списку; компактный вид; свайп для отметки | Прозрачность при совместном ведении, удобство длинных списков |
| **Grocy** | Режим «в магазине» (крупные элементы, только нужное); идея автопополнения: регулярные покупки как подсказки | Удобство у полки; меньше забытых регулярных товаров |

### Чего избегать (антипаттерны из отзывов)

- **«Бюрократия» мастер-данных** (Grocy, частично Tandoor и Mealie): нельзя требовать категорию, единицу или магазин при добавлении. Свободный текст добавляется сразу, нормализация идёт в фоне или потом.
- **Сортировка по алфавиту по умолчанию** (Mealie без лейблов): список должен сразу группироваться по отделам.
- **Скрытые жесты без подсказок** (KitchenOwl: долгое нажатие, запятая в поиске): у каждого жеста должна быть видимая альтернатива (кнопка или меню) и одноразовая подсказка.
- **Ручное обновление страницы** (Grocy web): синхронизация только автоматическая.
- **Создание сущностей через уход в другой раздел** (Mealie): новый товар или отдел создаётся прямо на месте.

## 3. Экраны

### 3.1. Главный экран — список

Структура сверху вниз:

1. **Шапка:** название списка (тап открывает переключатель списков, если их больше одного; списки отсортированы по последнему изменению, переименовать может любой участник), ряд круглых аватаров участников из Telegram (кто имеет доступ к списку), выбранный магазин (чип «🛒 Mercadona ▾»), меню «⋯».
2. **Строка ввода** закреплена сверху и всегда видна. При фокусе ниже открывается панель подсказок (п. 4).
3. **Список «Купить»**, сгруппированный по отделам в порядке выбранного магазина:
   - заголовок отдела: иконка, название, счётчик;
   - строка товара: чекбокс или тап по строке, название, заметка мелким шрифтом, аватар добавившего, если у списка больше одного участника;
   - отдел «Без категории» стоит последним, у него подсказка «перетащите товар в отдел».
4. **Кнопка «Куплено (N)»** (нативная нижняя кнопка Telegram, `MainButton`): видна, только когда есть зачёркнутые позиции; N — их число. Убирает из списка все зачёркнутые позиции и записывает их в историю одной покупкой. После нажатия — snackbar «Отменить» на 5 с: позиции возвращаются зачёркнутыми, запись из истории исчезает. Подтверждающего диалога нет.
5. Пустое состояние: короткая подсказка по вводу и несколько популярных товаров для быстрого старта. При первом входе без ссылки «Поделиться» автоматически создаётся список «Покупки» на языке пользователя.

Варианты отображения (настройка): **список** (по умолчанию), **плитки** с иконками, **компактный**.

### 3.2. Карточка товара (bottom sheet)

Открывается тапом по названию, а не по чекбоксу. Поля:
- название;
- заметка: количество или детали (свободный текст);
- отдел (выбор из фиксированного набора) — меняется у товара целиком: все его строки, текущие и будущие, переезжают в новый отдел;
- кто добавил и когда.

Действия: удалить, перенести в другой список. Сохранение автоматическое, без кнопки «Сохранить».

### 3.3. Режим «в магазине»

Включается кнопкой (Telegram BottomButton «Я в магазине») или автоматически при выборе магазина. В этом режиме:
- крупный шрифт и увеличенные зоны тапа;
- строка ввода скрыта за кнопкой «+»;
- экран не гаснет;
- зачёркнутые позиции остаются на месте, чтобы список не прыгал под пальцем;
- порядок отметок записывается для обучения порядка отделов.

По завершении — кнопка «Куплено», как на главном экране; незачёркнутое остаётся в списке.

### 3.4. История списка

У каждого списка есть история покупок. Каждое нажатие «Куплено» создаёт в ней запись: когда, кто нажал и какой набор позиций купили («9 ноября, 18:40 · Аня · молоко (2 л), хлеб, яйца»).

- Новые записи сверху; история подгружается страницами при прокрутке (курсорная пагинация по времени покупки), а не целиком.
- Хранится без ограничений по сроку.
- Тап по позиции в записи добавляет её в список снова с той же заметкой. «Повторить всю покупку» — позже.

### 3.5. Магазины и отделы

- Список магазинов и магазин по умолчанию (чьи это магазины — открытый вопрос, см. §11).
- Для каждого магазина — порядок отделов, редактируется перетаскиванием.
- Порядок дообучается автоматически: если товары отдела X раз за разом отмечаются раньше отдела Y, X поднимается. Ручная правка фиксирует порядок, автоматика его больше не переопределяет.
- Базовый набор отделов на языке пользователя (RU/ES; чьи это отделы — открытый вопрос, см. §11): Фрукты и овощи, Хлеб, Молочное, Мясо и рыба, Заморозка, Бакалея, Напитки, Бытовая химия, Гигиена, Прочее.

### 3.6. Настройки

Язык; вид списка; списки (создать, переименовать, удалить через экран подтверждения); участники списка и кнопка «Поделиться»; магазины; «не гасить экран в магазине»; уведомления.

## 4. Ввод товаров (самое важное)

- **Одна строка для всего:** поиск по своим товарам и добавление нового.
- **Парсинг строки:**
  - `молоко` → товар;
  - `молоко, 2 л` → товар + заметка (как в KitchenOwl);
  - `2 молока` и `молоко 2` — по возможности тоже распознавать количество.
  - Несколько товаров за раз: `молоко, хлеб; яйца 10` — разделитель `;` или перенос строки. Вставка многострочного текста из заметок добавляет всё сразу.
- **Подсказки при вводе:**
  1. совпадения в памяти позиций этого списка — только товары, которые уже вводились в этот список (подсказки из других списков не показываются) (с учётом опечаток и без учёта диакритики, что важно для испанского: «platano» = «plátano»);
  2. частые и недавние покупки;
  3. пункт «Добавить „…“» как новый товар.
- **Enter / кнопка «Добавить»** добавляет первый вариант; поле очищается и остаётся в фокусе для следующего товара.
- **Повторный ввод:** если товар уже есть в списке, создаётся ещё одна строка; дубли разрешены и не объединяются (ADR-0002). В подсказках у такого товара пометка «уже в списке».
- **Удаление из памяти** только скрывает подсказку: строки в списке и записи в истории остаются; повторный ввод возвращает товар в память.
- **Категория** у нового товара угадывается автоматически: словарь, позже опционально LLM. Если не угадали — «Без категории»; это не блокирует добавление.
- **Блок «Часто покупаем»** при пустом поле: топ-товары по частоте покупок, добавление в один тап.
- Позже: голосовой ввод через бота (голосовое сообщение → распознавание → позиции) и быстрый ввод текстом прямо в чате бота.

## 5. Отметка и удаление

- **Тап по чекбоксу или строке** — зачеркнуть позицию; повторный тап снимает зачёркивание. Зачёркнутая позиция остаётся в списке на своём месте.
- **«Куплено»** — все зачёркнутые позиции уходят из списка в историю одной покупкой.
- **Свайп вправо** — отметить, **свайп влево** — удалить с Undo. Обязательно отключить вертикальные свайпы Telegram, иначе жесты в списке конфликтуют с закрытием Mini App (см. п. 7).
- **Долгое нажатие и перетаскивание** — перенос в другой отдел; видимая альтернатива — выбор отдела в карточке.
- **Массовые действия** в «⋯»: «Снять все отметки».
- Тактильный отклик (HapticFeedback) на отметку, удаление и Undo.

## 6. Совместная работа и синхронизация

- У списка может быть несколько участников; у каждого Telegram-аккаунт. Права у всех одинаковые, включая удаление списка.
- **Поделиться:** кнопка «Поделиться» копирует ссылку `t.me/<bot>?startapp=<код>`, которая сразу открывает Mini App. Код случайный (не id списка), постоянный, сброса в MVP нет. Кто перешёл по ссылке, становится участником списка.
- **Покинуть и удалить:** «Покинуть список» убирает его только у себя; «Удалить список» — у всех, вместе с историей, без восстановления, через экран подтверждения «Список удалится у всех N участников». Когда уходит последний участник, список удаляется. Исключать участников нельзя.
- **Realtime:** изменения другого участника появляются без обновления (SSE или WebSocket) с мягкой подсветкой новой или изменённой строки.
- **Догонка после разрыва:** запрос изменений `changes?since=<version>` при возвращении в приложение (событие активации Mini App) и при переподключении.
- **Офлайн, best effort:**
  - последнее состояние списка кэшируется на устройстве;
  - отметки и добавления ставятся в локальную очередь операций с идемпотентными id и отправляются при появлении сети;
  - индикатор «офлайн / синхронизация».
- **Конфликты.** Правила по типу операции, а не «последняя запись побеждает»:
  - зачёркивание побеждает снятие, если они случились почти одновременно;
  - удаление побеждает редактирование;
  - одновременные добавления одного товара дают две строки, не объединяются.
- **Уведомления через бота** (опционально, с тихими часами):
  - «Аня добавила 3 товара в „Продукты“» — сгруппированно, не чаще раза в N минут;
  - «Список готов к походу» — по кнопке «Отправить список» в меню.

## 7. Особенности Telegram Mini App

- **Тема:** только цвета из `themeParams` (CSS-переменные `--tg-theme-bg-color`, `--tg-theme-text-color`, `--tg-theme-button-color`, `--tg-theme-secondary-bg-color`, `--tg-theme-hint-color` и т. д.). Своя палитра — только для иконок отделов. Тёмная тема получается автоматически.
- **Нативные элементы:**
  - `BackButton` — закрытие bottom sheet и выход из вложенных экранов;
  - `MainButton` — главное действие экрана: «Куплено (N)» на списке, «Я в магазине» позже;
  - `HapticFeedback` — отклик на действия;
  - `showConfirm` / `showPopup` — подтверждение опасных действий («Очистить купленное»).
- **Жесты и вьюпорт:**
  - при старте вызывать `ready()` и `expand()`;
  - `disableVerticalSwipes()` — чтобы свайпы и скролл списка не сворачивали приложение;
  - учитывать safe area и content safe area insets (особенно в fullscreen);
  - `enableClosingConfirmation()` — только пока есть неотправленные офлайн-операции.
- **Авторизация:** фронт передаёт `initData` на бэкенд; бэкенд проверяет подпись HMAC токеном бота и срок `auth_date`, затем выдаёт сессию. Нельзя доверять `initDataUnsafe` на клиенте.
- **Deep links:** `startapp=<код>` — подключение к списку и его открытие; в @BotFather включить Main Mini App.
- **Хранение на устройстве:** `CloudStorage` Telegram — для мелких пользовательских настроек (вид списка, последний список). Кэш списка и очередь офлайн-операций — в IndexedDB/localStorage с обработкой ошибок.
- **Экран не гаснет:** проверить поддержку в текущей версии Telegram WebApp API; иначе Screen Wake Lock API браузера.
- **Ограничение:** в Mini App нет фоновой синхронизации и push — уведомления только сообщениями бота.
- **Опционально:** `addToHomeScreen()` — ярлык на домашний экран для быстрого доступа.
- **Библиотека:** `@telegram-apps/sdk` (React-биндинги есть) или официальный `telegram-web-app.js`.

## 8. Минимальная модель данных (для понимания UI)

- `user` — telegram_user_id, name, avatar, lang.
- `list` — id, name, created_by, share_code.
- `list_member` — list_id, telegram_user_id, joined_at.
- `item` — память позиций списка (удаляется вручную из подсказок): id, list_id, name, normalized_name, category_id, icon, purchase_count, last_purchased_at.
- `list_entry` — id, list_id, item_id, note, added_by, added_at, checked, checked_at, checked_by.
- `purchase` — id, list_id, purchased_at, purchased_by; `purchase_entry` — purchase_id, item_id, note (состав покупки для истории).
- `category` — id, name_ru, name_es, icon: фиксированный системный набор.
- `store` — id, name (владелец — открытый вопрос); `store_category_order` — store_id, category_id, position, is_manual.
- `checkout_log` — store_id, item_id, category_id, checked_at, sequence (для обучения порядка).
- `version` — монотонный счётчик изменений списка для `changes?since`.

## 10. Критерии приёмки UI

- Добавление товара с клавиатуры: ввод + Enter, без дополнительных тапов; поле остаётся в фокусе.
- Ни одно добавление не требует выбора категории, единицы или магазина.
- Изменение у второго участника появляется ≤ 2 с без действий пользователя.
- Каждое разрушающее действие отменяется (Undo ≥ 5 с) или требует подтверждения.
- Свайпы по строкам не закрывают Mini App.
- Интерфейс корректен в светлой и тёмной темах Telegram, на iOS и Android, на экране 360 px.
- Без сети отметки не теряются и синхронизируются после восстановления.
- Поиск находит товар без учёта регистра и диакритики, с одной опечаткой.

## 11. Открытые вопросы

- Чьи магазины: общие, свои у каждого списка или у каждого пользователя? Решаем на этапе «Следом».

Решено: количество — свободный текст (заметка); ввода в чате бота в MVP нет; отделы — фиксированный системный набор; иконки — эмодзи.
